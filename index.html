Content Credentials (C2PA) Cheat Sheet

One page on reading the provenance data inside an image file — the fields that say whether a picture came from a camera, an editor, or a generative model, and why most images you find online carry none of it.

What a manifest is

A C2PA manifest is a signed record embedded in the file (a JUMBF box in JPEG/PNG/WebP/HEIC). It lists assertions — what tool made the image, which actions were applied, thumbnails of ingredients — and a claim signature over all of it plus a hash of the pixel data. The active manifest is the most recent one; earlier manifests appear as ingredients.

Digital source type (the field that answers "was this AI?")

Found on the creating action, as an IPTC vocabulary URI ending in one of these values:

ValueMeaningGenerative AI?
trainedAlgorithmicMediaCreated by a model trained on sampled contentYes
compositeWithTrainedAlgorithmicMediaReal content combined with generated parts (e.g. generative fill)Partly
algorithmicMediaMade by an algorithm with no training data (procedural, fractal)No — computer-generated, not AI
compositeSyntheticComposite that includes synthetic elementsUnclear — read the actions
digitalCaptureCaptured by a digital camera or scannerNo
screenCaptureA screenshotSays nothing about the original
digitalArtCreated by a person with softwareNo
Common mistake: treating algorithmicMedia as "AI-generated". In the IPTC definitions the word trained is what separates generative AI from ordinary computer graphics.

Actions you'll see

  • c2pa.created — the asset was made here (carries the digital source type).
  • c2pa.opened — an existing asset was opened as the starting point.
  • c2pa.edited, c2pa.color_adjustments, c2pa.cropped, c2pa.resized — edits after creation.
  • c2pa.placed — another asset (an ingredient) was placed into this one.
  • c2pa.converted — format change, e.g. PNG to JPEG.

Validation: integrity vs. trust

Readers report two different things, and mixing them up causes most wrong conclusions:

QuestionCodes to look forIf it fails
Did anything change after signing?claimSignature.validated, assertion.dataHash.matchThe file was altered — treat the manifest as a claim, not proof
Is the signer on the C2PA trust list?signingCredential.trusted / signingCredential.untrustedContent may be intact; only the certificate isn't recognised

Overall states are Invalid, Valid and Trusted. A file can be "Invalid" overall purely because of the certificate check while its hashes and signature all pass — read the individual codes before calling an image tampered.

What strips Content Credentials

  • Screenshots — a new file with no manifest.
  • Most social and chat uploads — platforms re-encode images and drop the metadata box.
  • Re-saving or converting in tools that don't write C2PA — the old manifest is simply not copied.
  • Deliberate removal — anyone can strip it; credentials prove origin when present, never absence when missing.
So: "no credentials found" is the normal case for images from the web and tells you nothing on its own. That's where pattern-based detectors come in.

Reading a manifest yourself

# Python (official binding)
pip install c2pa-python
python -c "import c2pa,sys; print(c2pa.Reader(sys.argv[1]).json())" photo.jpg

# CLI
c2patool photo.jpg

In the browser, @contentauth/c2pa-web reads manifests client-side via WebAssembly, so the image never leaves the device.
